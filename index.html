03 / Mindset

What is an advanced beginner?

From usage to engineering
“

An advanced beginner does not expect an LLM to be perfect. They know how to identify uncertainty, investigate failures, and improve the surrounding system.

01
Beginner

Can ask an LLM to complete a task.

02
Advanced beginner

04 / Capability 02

Write versioned prompts

Prompts are engineering artifacts

Move beyond one-off inputs

A production prompt should be stored, reviewed, tested, and released like application code.

01

Give each important prompt a stable identifier and version number.

02

Record why a prompt changed and which problem the change solves.

03

Evaluate the new version against a reusable set of test cases.

04

Keep a rollback path when a new version reduces output quality.

prompts/customer-summary.yaml

v1.3.0 
id: customer-summary
version: 1.3.0
owner: customer-platform

system: |
  Summarize the customer case using
  only the provided evidence.

output:
  format: JSON
  include_sources: true

evaluation:
  dataset: support-cases-v4
  minimum_score: 0.90

changes:
  - Reject unsupported conclusions
  - Require a source for each claim

05 / Capability 03

Choose local vs cloud

Match deployment to constraints

The right answer depends on data sensitivity, cost, quality requirements, latency, scale, and operational capacity.

⌂
Option A

Local model

  • Best when Sensitive data must remain in a controlled environment.
  • Cost pattern Higher infrastructure effort, predictable usage cost.
  • Trade-off More operational ownership and potentially lower quality.
VS
☁
Option B

Cloud model

  • Best when Strong capabilities and rapid delivery are priorities.
  • Cost pattern Usage-based pricing with limited infrastructure setup.
  • Trade-off Vendor dependence and additional data-governance review.

06 / Decision Framework

Ask these questions first

Decision checklist
◇ 01

Data sensitivity

Can the input leave the organization, region, or controlled network?

$ 02

Total cost

Compare API usage with hardware, hosting, maintenance, and engineering effort.

⚡ 03

Latency and scale

How quickly must the system respond, and how variable is the traffic?

✦ 04

Required quality

Can a smaller model meet the acceptance criteria for this specific task?

Useful rule

Choose the smallest and simplest deployment that meets your measurable quality, security, and performance requirements.

07 / Capability 04

Own AI-generated output

Generated does not mean approved
✓

You remain accountable

The model can assist with a deliverable, but it cannot accept professional, contractual, or legal responsibility for it.

01

Verify factual claims

Check names, dates, calculations, references, and technical assertions.

02

Check contract terms

Confirm that the result matches the agreed scope, format, acceptance criteria, and confidentiality terms.

03

Review legal requirements

Check privacy, intellectual property, regulatory, and data-retention obligations.

04

Record human approval

Make a qualified person responsible for the final release.

08 / Practical Example

Putting the four capabilities together

Customer support assistant
The situation

An AI assistant provides a customer with an outdated refund policy.

Instead of immediately switching models, the team investigates the full pipeline.

01
Diagnose

The retriever selected an archived policy document.

02
Version

Prompt v2.1 requires policy dates and source links.

03
Deploy

Cloud inference is retained, but sensitive fields are removed before submission.

04
Own

High-value refunds require human review before sending.

09 / Key Takeaways

Your advanced-beginner toolkit

Remember these four ideas
01

Diagnose before changing

Determine whether the failure comes from retrieval, context, instructions, or the model itself.

02

Version what matters

Store critical prompts with tests, ownership, release notes, and rollback options.

03

Choose using constraints

Let data sensitivity, quality, cost, latency, and operations drive deployment decisions.

04

Keep humans accountable

Review AI-assisted work against factual, contractual, and legal requirements.
